# 決定記録

要件定義の協議で確定した仕様判断を記録する。
本文書の ID は他文書から「仕様決定 A」のように参照する。

| ID | 項目 | 決定内容 | 決定日 |
|----|------|----------|--------|
| A | LUTの適用先と出力形式 | `.cube`（DaVinci Resolve、Adobe系、OBS等で使える汎用形式）とPNG画像LUT（HaldCLUTまたはReShade形式）の両形式で書き出す | 2026-09-27 |
| B | 調整パラメータの範囲 | 露出、コントラスト、彩度、色温度、色相、RGBカーブ、リフト・ガンマ・ゲイン。後から追加できる拡張可能な設計とする | 2026-09-27 |
| C | 配布形態 | 静的Webアプリとし、GitHub Pagesでホストする | 2026-09-27 |
| D | LUTサイズ | `.cube` は33、PNGアトラスは64 | 2026-09-27 |
| E | 調整値の保存 | JSONプリセットとして保存・読み込みできる。LUTから調整値への逆変換は原理的に不可能なため、再編集はプリセット経由とする | 2026-09-27 |
| F | 既存LUTの読み込み | 初期スコープ外とする。既存LUTのプレビュー適用や形式変換としてのインポート自体は可能だが、作成が主目的のため後回し | 2026-09-27 |
| G | LUT適用済み画像の書き出し | 実装する。LUTを焼き込んだ画像をPNGで保存できる | 2026-09-27 |
| H | 成果物の置き場 | 新規GitHubリポジトリ `LUT-Studio` を作成する | 2026-09-27 |
| I | 画像枚数の制限 | 上限は設けない。最低4枚の同時プレビューを保証し、メモリが許す範囲で追加できる | 2026-09-27 |
| J | PNG画像LUTの配置形式 | HaldCLUT形式（正方形配置）とReShade形式（横長ストリップ）の両方を書き出し可能とし、書き出し時に選択する | 2026-09-27 |
| K | アイソレーション系LUT | 「分離」（指定色相範囲だけ彩色を残し、範囲外を脱色する部分色残し）のみを本実装とする。色相の選択対象は複数登録でき、中心色相はスライダ・カラーピッカー・プレビュー画像上のクリック（元画像の画素から拾うスポイト）で指定する（肌色＋離れた特定色を同時に残す用途）。選択範囲の確認は、各選択対象に表示する色相環グラデーションバー（残る色を着色、範囲外を脱色した見た目）と、書き出しLUTに影響しないプレビュー側のマスク表示トグルで行う | 2026-09-27 |
| L | UIテーマ | ダーク・ライトグレー・ブラック・ホワイトの4種をモノクロ基調で提供する。写真調整の視認を邪魔しないよう彩度を持ったアクセント色は使わない。選択はlocalStorageに保存する | 2026-09-27 |
| M | スマホ版UI | 画面幅640px以下をスマホ版とする。調整パネルは画面下部約30%に固定し、上部をプレビューに使う。画像は中央揃えとし、表示サイズの既定は最大(90%)とする（保存済みの設定があればそちらを優先）。RGBカーブはパネル幅いっぱいに拡大し、ポインターイベント化とダブルタップ削除でタッチ操作に対応する。タッチスクロール時の誤操作を防ぐため `<details>` で格納し、既定はスマホで畳む・デスクトップで展開（ユーザーが切り替えた状態は維持）。リフト・ガンマ・ゲインも同じ `<details>` 機構で格納する。展開時のキャンバスは下ペインに収まる高さ（30dvh−6rem）に抑えて中央寄せとする。LUT書き出し（.cube／画像LUT）はPC作業を想定するためスマホ版では表示しない。LUT適用済み画像のPNG書き出しとJSONプリセットはスマホ版でも利用できる | 2026-09-27 |
| N | 画像名の省略 | キャプションのファイル名が表示幅に収まらないとき、拡張子は末尾に残したままベース名を省略表記（ellipsis）する。判定基準の表示幅は画像幅（カード幅＝タイル幅に固定）とし、縮小表示ではより短く省略される | 2026-09-27 |
| O | 画像の個別削除 | 各画像のキャプション行に削除ボタン（✕）を置き、その画像だけをプレビューから除去する。削除時にWebGLレンダラとImageBitmapを破棄する | 2026-09-27 |
| P | LUT書き出しファイル名 | 保存するLUT名にローカル時刻の `_yyMMddhhmm` を付ける（例: `lut-studio_2609271255.cube`）。画像PNG書き出しとJSONプリセットは対象外 | 2026-09-27 |
| Q | 大きな画像の書き出し | 書き出しは原則元画像のフル解像度（決定G）だが、canvas上限を超えるとブラウザがラスタを黙って縮小し「高解像度だが粗い」出力になるため、タッチ中心端末では長辺4096pxへ事前縮小してから書き出す。さらにcanvas確保やエンコードが失敗した場合は長辺を半分ずつ縮小して再試行する（下限はプレビュー読み込み済みサイズ）。縮小時はステータスに出力寸法を明示する | 2026-09-27 |
| R | 既存LUT読み込みの対応形式 | `.cube`（LUT_3D_SIZE のみ、サイズ2〜256）とPNG画像LUT（HaldCLUT・ReShade、寸法署名で自動判別）を読み込み対応とする。1Dのみまたは併記の `.cube`、`.3dl`・`.look`・`.csp`・ICC などの形式、レイアウト署名に合わないPNGは対象外 | 2026-09-27 |
| S | 読み込みLUTの合成位置 | 読み込んだLUTは中立LUTの代わりとなるベースLUTとし、「ベース→調整」の順に合成する（出力=調整(ベース(入力))）。LUTから調整値への逆変換は行わず、読み込み後も調整値は中立のまま（決定Eと整合） | 2026-09-27 |
| T | LUT読み込みの入口 | パネルの「LUTを読み込み」ボタンから `.cube` とPNGを受け付ける。画像ドロップゾーンは拡張子 `.cube` のみをLUTとして振り分け、PNGは写真との区別がつかないため常に画像として扱う | 2026-09-27 |
| U | 読み込みLUTの保持 | ベースLUTは元サイズのまま保持し、サイズ差の吸収は焼き付け時の三線形補間サンプリングに委ねる。ベースLUTはJSONプリセットに含めない（プリセットは調整値のみ、決定E）。再読み込みは置換とし、「解除」操作で中立に戻す | 2026-09-27 |
| V | スマホ版でのLUT読み込み | 読み込みUIはスマホ版では表示しない。LUT書き出しと同様にPC作業を想定する機能として、決定Mの非表示規則に合わせる。ドロップゾーンの `.cube` 振り分け自体は画面サイズに依らず動作する | 2026-09-27 |
| W | ベースLUTの適用強度 | 読み込んだベースLUTに 0〜100% の適用強度スライダーを設ける（既定100）。合成は `入力 + s×(ベース(入力) − 入力)` の線形補間とし、0% は未適用（中立LUTと同等）、100% でフル適用。強度はプリセットに含めず、ベースLUT未読み込み時はスライダーを表示しない | 2026-09-27 |
| X | 調整の適用順序 | 現状の順序（露出 → 色温度 → コントラスト → 彩度 → 色相回転 → カーブ → リフト/ガンマ/ゲイン → 0〜1丸め）を維持する。Unity Post Processing Stack や Lightroom 系ツールと同様に「線形系の全体補正 → 色相・彩度 → トーン整形 → 仕上げのグレード」の流れに沿っており、露出を先頭・彩度と色相を後段に置く配置は慣行と一致する。カーブとLGGの前後関係はツール間で分かれる（Unity は LGG→カーブ、Lightroom 系はカーブ→LGGの順）。現行の LGG 後段では、カーブで沈めた暗部をリフトが持ち上げる仕上げのグレードとして各スライダの効きが出力まで保証される利点があり、入れ替えても正解が増えるわけではないため変更しない。旧来のアイソレーション中間位置は決定Yの位置選択に整理して吸収する | 2026-09-28 |
| Y | アイソレーションの適用位置 | アイソレーションの適用箇所を `position` で選択できるようにする。`"first"` は調整チェーンの最初（ベースLUT直後、原画像の色相で選択し脱色後の色に残りの調整がかかる）、`"last"` はチェーンの最後（LGG適用後、調整済みの色で選択し脱色が最終出力になる）。位置はJSONプリセットに保存する。`position` を持たない旧プリセットは `"last"` として読み込む。これは旧実装（色相回転後・カーブ前の中間位置）が露出〜色相回転の結果でマスクを評価していたためで、`"last"` は選択基準が調整後の色である点を維持したまま差分をカーブとLGGの2段に留める。`"first"` に寄せると選択基準が原画像へ戻り色相回転や色温度の効果がマスクに乗らなくなるため、丸め先としては遠い。また `"last"` では脱色後に他の調整がかからず、範囲外が輝度であることが出力レベルで保証される | 2026-09-28 |
